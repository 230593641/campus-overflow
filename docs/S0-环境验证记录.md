## 1. Issue #1 · Docker 环境（受阻）

**无法在本机执行的原因**：本机未安装 Docker（`docker` 与 `docker compose` 均不是可执行命令），
因此“起容器 + Navicat/RedisInsight 连接”这一步无法在当前环境中验证。这不是配置错误，是缺少运行时。

**已完成的部分**：对 `deploy/docker-compose.yml` 做了逐项静态核查，结论是文件可用，无需改动。

| 检查项 | 结果 |
| --- | --- |
| 服务定义 | `mysql`(3306) / `redis`(6379) / `backend`(8080) / `web`(80) + `profiles: observability` 下的 prometheus/grafana |
| MySQL 参数 | `utf8mb4` / `utf8mb4_0900_ai_ci` / `--ngram-token-size=2` / `--innodb-ft-enable-stopword=0` / `--default-time-zone=+00:00`，与 ADR-005 要求一致 |
| 账号与库 | root=`root_dev_pwd`（可被 `MYSQL_ROOT_PASSWORD` 覆盖）、业务账号 `campus` / `campus_dev_pwd`、库 `campus_overflow` |
| 健康检查 | mysql `mysqladmin ping`、redis `redis-cli ping`、backend `/actuator/health/readiness`，后端 `depends_on` 两个中间件 `service_healthy` |
| 数据持久化 | 命名卷 `mysql-data` / `redis-data` / `grafana-data` |
| 端口占用风险 | 3306 / 6379 / 8080 / 80，若本机已有 MySQL/Navicat 本地实例需先停掉或改端口映射 |

**待办（装好 Docker Desktop 后按顺序执行）**：

```bash

# 2) 确认两个容器都健康（应看到 healthy）

# 3) 连通性自检

# 4) 客户端连接参数
#    Navicat : 127.0.0.1:3306  campus / campus_dev_pwd  库 campus_overflow
```

| 分类错位 / 漏项 | — | 0 | ✅ |

**校验方式**（已固化为脚本，可重复执行）：

```bash
node scripts/verify-task-list.mjs            # 失败时退出码 1
node scripts/verify-task-list.mjs --detail   # 打印逐文件对照
```

脚本校验四件事：① 每文件文档方法数 = 源码 `TODO(S2|S3)` 标记数 ÷ 2；② 每个方法的 Sprint 归属与源码标记一致；
③ 文档与源码双向无漏项；④ TODO 消息里写的类名与所在文件一致（防止复制粘贴留错名）。

> 关于“107 个方法但有 32 个文件名下出现 214 处标记”：源码里每个待实现方法都有两处标记
> ——方法上的 `// TODO(S2)：实现 X.y` 注释，和 `throw new UnsupportedOperationException("TODO(S2)：X.y 尚未实现")`。
> 因此按“标记数 ÷ 2”才是方法数。重载方法（如 `NotificationProjector` 的 8 个 `on(...)`、`SearchIndexProjector` 的 10 个、
> `ReputationEventHandlers` 的 5 个、`SearchQuery` 的 2 个 `terms(...)`）在文档中逐个列出，脚本按“文件#方法名”去重后与文档条目数比对，两边都是 32/107。

**Sprint 分布明细**：S2 = Q&A 领域层 6 个文件 + 应用层 6 个文件；S3 = Discovery 领域 4 + 应用 4、Reputation 领域 5 + 应用 7。

## 4. Issue #4 · 本地测试（通过：恰好 38 个失败）

```bash
cd backend
export JAVA_HOME=<jdk-21>           # 必须 JDK 21；用 17 会编译失败（release 21）
mvn -B test "-Dmaven.test.failure.ignore=true"
```

结果（本机实测）：

| 指标 | 数值 |
| --- | --- |
| 编译 | ✅ 27 个模块全部编译通过（无依赖错、无环境错） |
| 参与执行的测试 | 54 个（14 份 surefire 报告） |
| 失败总数 | **38**（Failures 4 + Errors 34） |
| 失败原因 | **38/38 全部为 `java.lang.UnsupportedOperationException: TODO`** |

**注意一个坑**：不带参数执行 `mvn test` 时 Maven 默认 fail-fast，会在第一个失败模块（`co-qa-domain`）
就停下，只看到 15 个失败——这会让 Issue #4 的验收看起来“不是 38”。要统计全量必须加
`-Dmaven.test.failure.ignore=true`（让 reactor 继续跑完再汇总）。或者单模块跑：

```bash
mvn test -pl co-qa/co-qa-domain -Dtest=QuestionTest     # 红→绿 的日常循环
```

另外：单元测试与集成测试（`mvn verify`）的区别在于后者需要 MySQL + Redis（依赖 Issue #1）。

## 5. Issue #7 / #8 的阻塞

- **#7 前端**：CI 上已证明 `npm install` → `npm run typecheck` → `npm run build` 三步可绿；本机执行时被受限沙箱拦截
  （`spawn EPERM`，子进程管道被禁止），属于执行环境限制而非项目问题。在普通终端跑即可：
  ```bash
  cd frontend && npm install && npm run dev    # http://localhost:5173
  ```
- **#8 后端 dev profile**：需要先有 #1 的 MySQL + Redis，否则启动会在数据源/会话存储处失败。
  ```bash
  mvn spring-boot:run -pl co-bootstrap -Dspring-boot.run.profiles=dev
  # http://localhost:8080/swagger-ui.html
  ```
